最后核查：2026-10-08。软件更新、迁移和用户操作可能改变现状；执行前须重新检查路径、联接目标、运行进程及相关配置。不要把历史大小当成当前大小。

## agent 使用这些资料的方式

- 用户询问数据位置、空间占用、清理、迁移、规则或 Skills 路径时，先查本文件；实际操作前只读复查相关项。
- 普通写代码或写作任务不必加载本文件；选择实际项目目录作为工作目录。
- 公共规则的源在 rules/common.md，同步工具把标记块分发到各客户端入口。规则属于副本；共享 TODO.md 则是所有 agent 直接读写同一文件，不分发副本。
- 软件私有会话数据库、自动记忆和认证不是公共知识库，不应整份复制进上下文或公共文档。
- 引用资料时保留来源和核查日期。后续实际完成迁移或验证后，局部更新本文件及对应操作记录，不覆盖其他 agent 的更新。

## 迁移和清理边界

- “记录了位置”“列入 TODO”都不代表已授权删除或迁移。
- Junction 的入口和目标指向同一份内容；通过入口清空文件也会影响目标。不要直接对入口递归清理。
- 迁移先停止相关写入进程，再复制、核验、保留备份、切换入口、启动验证；失败必须明确停止并保留恢复路径。
- 数据库及 WAL 等附属文件需要一致性处理，不能只凭文件名选择性搬迁。
- 迁移后检查 AgentKit 分发路径、工具运行时和 MCP 接入是否仍有效。tools/sync.ps1 可能借用 WorkBuddy 内置 Python，不能忽略这个依赖。
- 历史备份 C:/Users/29485/.workbuddy.backup-20260928-151235 的删除事项曾记为 TODO-001；其当前状态以 TODO.md 和现场检查为准，本文件不宣称它仍存在或已删除。
