## 3. VS Code 用户数据迁移至 E 盘

### 决策与范围

用户希望程序继续在 D 盘、数据迁入 E 盘，以后仍按原方式使用。先讨论官方启动参数与便携模式：启动参数需要覆盖快捷方式、终端与右键等入口；便携模式需要相应发行版。最终用户明确授权通过 Junction 迁移至 `E:\SoftData\VscodeData`。

迁移的是 `C:\Users\29485\.vscode` 与 `C:\Users\29485\AppData\Roaming\Code`，不是 D 盘程序自带的 `resources\app\extensions`。内置扩展、用户安装扩展、扩展安装包缓存是不同目录。

### 执行与证据

1. 检查 VS Code 未运行、目标目录为空、E 盘空间足够，扫描源树链接。
2. 使用 Robocopy 复制，保留文件数据、属性及时间；没有使用会删除目标额外文件的 `/MIR`。
3. 核对文件/目录清单，再逐文件 SHA-256 比较：`.vscode` 39,785 文件、2,757,782,002 字节；`Code` 19,975 文件、5,511,371,538 字节。共 59,760 文件全部一致。[校验摘要](../证据/VSCode迁移校验摘要.json)只保留汇总，不含每个文件的哈希。
4. C 盘原目录改名为 `.vscode.pre-E-migration`、`Code.pre-E-migration`；原名建立指向 E 盘的 Junction；核实两条路径实际为同一目录。
5. 通过原 `code.cmd --list-extensions --show-versions` 成功列出扩展，但后来证明这不足以确认 GUI 正常。
6. 删除备份的 PowerShell 命令被自动审批以 `blocked by policy` 拒绝，命令未启动，两个备份均仍在。没有改用另一种工具绕过删除限制。
