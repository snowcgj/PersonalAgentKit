## 任务背景

用户觉得 C 盘有点慢，想清理一下电脑磁盘。

这个任务的核心不是“看到大文件就删”，而是先弄清楚：

- C 盘当前空间压力有多大；
- 哪些目录是真正占空间的大头；
- 哪些是可重建缓存；
- 哪些是软件本体、工具链、用户数据或项目状态；
- 哪些操作需要用户明确确认后再做。

当前任务已暂停。用户想先去做其他事情，后续可能在新的 Codex 对话窗口中读取本文档，恢复上下文并继续处理。

## 工作原则

- 先做只读盘点，再决定是否清理。
- 不直接运行系统清理、安装脚本、包管理器、注册表修改、环境变量修改等有副作用操作，除非用户明确同意。
- 递归删除目录前，必须先确认目标路径是精确路径。
- 区分“缓存”“工具链”“项目文件”“用户数据”“软件状态”。
- 不手动搬移已安装软件目录。已有软件如果要迁移，应通过软件自带迁移功能，或者卸载后重装到目标盘。
- 磁盘剩余空间、缓存大小、正在运行的进程都会变化；下次继续前必须重新只读核验。

## 下次建议步骤

下次继续时，先重新只读核验，不要直接沿用本文档里的空间数字。

建议按风险从低到高继续：

1. 重新检查并考虑删除 `C:\Users\29485\AppData\Roaming\Code\CachedExtensionVSIXs`。这是 VSCode 扩展安装包缓存，不是已安装扩展本体。
2. 重新检查并清理 `C:\Users\29485\AppData\Local\Temp`。正在被占用的文件跳过即可。
3. 重新检查并清理 `C:\Users\29485\AppData\Local\npm-cache`。影响是以后 npm install 可能重新下载包。
4. 先拆开查看 `C:\Users\29485\.cache`，不要直接整体删除，因为这个目录名太泛。
5. Unity cache 暂时先不处理。它原则上是可重建缓存，但可能导致 Unity 以后重新下载包，离线打开旧项目时可能受影响。
6. `Code\User\workspaceStorage` 谨慎处理。它不是源码，但可能包含 VSCode 工作区状态和扩展状态。
7. Edge、WPS、Tencent 相关数据优先通过软件自带清理功能处理，不建议直接删目录。
8. 如果用户反馈主要是开机慢或登录后卡顿，再处理启动项。之前观察到启动项偏多，包括 QQ、微信、Steam、Epic、OneDrive、百度网盘检测、GameViewer、Kite、Clash Verge、ActivityWatch、Everything 等。
