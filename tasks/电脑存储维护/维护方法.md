# 后续维护方法

这是从本次实际工作整理出的操作方法，不是自动执行清单。具体状态与路径先看 [当前状态](当前状态.md)。

## 1. 从目标开始，再做局部盘点

先分清用户要释放空间、整理目录，还是解决性能问题。三者不同：17 MiB 的数据库对容量帮助小，但可能影响根目录整洁；显示为 Healthy 也不能解释所有卡顿。

先读盘容量和顶层目录，再深入大的候选项。避免反复全盘扫描；小文件很多时，复用已有结果并重新测量要操作的路径。统计标明时间、字节、错误数、链接跳过数，父子目录不要加两次。不要跟随 Junction 把 E 盘迁移数据算到 C 盘。

## 2. 删除前判断文件扮演什么角色

| 类型 | 判断与处理 |
|---|---|
| 软件本体、运行库 | 优先正规卸载或软件自身管理入口，不能按“大文件”删除 |
| 明确的下载/编译缓存 | 说明重建或重下载代价，关闭关联应用，核对准确路径 |
| 设置、数据库、扩展状态、工作区状态 | 保留或有回退地迁移；名字有 cache/db 不代表无价值 |
| 项目源码与素材 | 和软件残留分开，不因卸载编辑器自动获准删除 |
| 系统组件、安装器缓存、驱动 | 不整目录手动删除，不凭逻辑大小估计收益 |

版本号较小不等于没在使用；同时存在多个版本时，核对启动入口、注册信息和运行进程加载的模块。未加载只是当次证据，清理前退出程序，清理后重新测试。

不要整删模糊的 `.cache`、`AutoUpdate`、`components` 或 `module`。百度更新包案例说明 AutoUpdate 同时包含更新器本体和下载包。

## 3. 数据迁移的完整验证链

1. 核实软件支持的官方数据路径机制，以及用户常用的启动方式。
2. 确定程序、用户扩展、用户数据、扩展独立缓存的边界。
3. 保存工作并退出应用；确认没有相关进程继续写库。不能为了迁移强制丢弃未保存工作。
4. 检查源和目标是否有内容、空间够不够、是否为链接。
5. 复制后核对文件/目录清单与内容；较大迁移保留文件数、总字节数和哈希校验摘要。不要将汇总 true 描述成保存了所有逐文件哈希。
6. 保留旧目录回退副本，再建立 Junction 或更改应用支持的路径。
7. 检查链接指向与读取，再正常启动 GUI，检查设置、布局、扩展、项目及必要账户。CLI 能列扩展不代表 GUI 和认证均正常。
8. 发生异常时先比对旧副本；不要边运行边用旧数据库覆盖新库，也不要将所有登录提示归咎于迁移。
9. 用户确认稳定后再删除原备份；这是另一个有授权、有验证的步骤。保留备份期间没有释放它占用的原盘空间。

本次 VS Code 方案保留原访问路径，因此快捷方式、任务栏搜索、终端、右键入口通常不必分别加启动参数。若以后链接损坏，先核实 E 盘目标和链接，再考虑软件问题；不要直接在原名上建立普通目录造成数据分叉。

## 4. 删除与失败处理

- 每次递归删除前重新核实绝对路径、目录类型、内部链接、进程与保留项目。不把未经检查的路径列表交给另一 shell 拼接删除。
- 明确“待删的备份目录”和“使用中的 Junction/目标数据”不是同一件事。
- 自动审批返回 `blocked by policy` 时，记录拒绝发生在执行前还是执行后；本轮多次是进程启动前拒绝，实际没有删除。不得更换工具或隐藏命令来绕过拒绝。
- 如果由用户手动删除，记录执行者，随后检查路径是否仍存在、应用是否正常、回收站是否仍占空间。
- 目录突然消失可能是用户动作、软件自动更新或其他操作；不能事后把它算成 agent 已成功删除。
- 只把有后验核查的项目记为完成。常见位置复查通过不等于全盘每个文件都已排除。

## 5. 回退原则

VS Code 两个 `pre-E-migration` 备份目前仍存在。若确需回退：先退出所有相关窗口/进程，备份 E 盘迁移后新增或改变的数据，核实 C 盘原名确为正确 Junction；只移除链接入口而非递归删除 E 盘目标，再恢复备份名称。回退可能丢失迁移后的状态，不能不比较就覆盖。本段是说明，不是即刻授权或可盲跑脚本。

布局问题只恢复已定位的状态项；修改 SQLite 前应用必须退出，并先备份相应数据库。重新启动后状态可被应用重算，因此最终仍须看界面与用户确认。

对两个 D 盘数据库，本次只加了 Hidden 位。若以后用户要求撤回这一显示属性，保留其他属性：`cache.db` 原为 32，`mdbx.dat` 原为 8224。更稳妥的是只撤销 Hidden 位，而不是覆盖整个属性集合。

## 6. 常用只读检查示例

以下是方法示例，变量要换成当前经过确认的准确路径；没有删除命令。

```powershell
# 文件或链接是否存在、链接指向与属性
Get-Item -LiteralPath 'C:\Users\29485\AppData\Roaming\Code' -Force |
    Select-Object FullName, Attributes, LinkType, Target

# 磁盘实际容量与空闲字节
Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" |
    Select-Object DeviceID, Size, FreeSpace

# 进程可执行文件位置；避免无关地输出完整参数和敏感数据
Get-CimInstance Win32_Process |
    Where-Object Name -eq 'quark.exe' |
    Select-Object Name, ProcessId, ExecutablePath
```

未知文件归属：先读文件元数据、文件头和与任务相关的标识，不上传数据库内容到网站。必要时用 Microsoft Process Monitor 过滤精确路径；ReadFile 是读，WriteFile 是写，CreateFile 也可能只是打开。索引/杀毒软件读过文件不证明是创建者；无捕获不证明文件无用。当前用户已暂缓此项，需新指令才继续。

## 7. 怎样补充下一次记录

```markdown
### 事项
- 时间与目标：
- 授权范围：
- 操作前：完整路径、字节数、类型/链接、进程、保留边界
- 依据：现场证据 / 历史记录 / 推断
- 操作：执行者、具体内容；若失败，记录实际影响
- 操作后：路径检查、功能检查、空间变化
- 回退条件与限制：
- 关联待办：只引用 D:\AgentKit\TODO.md 中的编号
```

每次只更新相关条目，更新前读最新文件。历史日志保留当时结论并追加纠正，不把旧推断润色成确定事实。永久档案只留必要的摘要、说明和可验证元数据，不收录凭据、聊天数据库、整段环境变量或海量调试日志。

## 参考资料与证据等级

- [VS Code 命令行参数](https://code.visualstudio.com/docs/configure/command-line)：官方路径参数说明。不同启动入口需一致，不能只改一个快捷方式便承诺全局生效。
- [VS Code 便携模式](https://code.visualstudio.com/docs/setup/portable)：官方机制；Windows 安装版不能简单假定建 data 目录就变为受支持的便携版。
- [Cocos 安装与启动](https://docs.cocos.com/creator/3.8/manual/en/getting-started/install/) 与 [全局扩展位置](https://docs.cocos.com/creator/3.8/manual/en/editor/extension/install.html)：解释 Dashboard、编辑器和用户扩展的分离；不能直接证明本机残留范围。
- [Cocos 历史卸载问题](https://forum.cocos.org/t/topic/151941)：版本与权限案例，仅作线索，不套用到全部版本。
- [libmdbx 文件名定义](https://github.com/isar/libmdbx/blob/master/mdbx.h)：说明 mdbx.dat 是默认数据库文件名；无法据此识别哪个应用创建了本机文件。
- [Microsoft Process Monitor](https://learn.microsoft.com/en-us/sysinternals/downloads/procmon)：后续若获授权，可用于文件访问归属监测；本轮未安装或运行。
