## 记录约定

沿用公共库的四级标记：

- **现场核验**：本机会话中工具的实际结果；注明时间与范围。
- **用户确认**：用户报告的使用感受；不扩写成所有功能均测试通过。
- **历史记录**：来自较早检查；不能直接当作最新事实。
- **推断 / 待验证**：证据不足，不作为处理依据。

补充约定：

- 性能问题少有单一根因。给出「嫌疑排序」时应同时写明排序依据，**不把相关性写成因果**。
- 未执行修复的结论一律标注为「尚未验证」，不能用「建议有效」替代实测。
- 时间用本地时间（Asia/Shanghai）；容量数值优先保留字节，正文用 GiB/MiB。
- 记录不构成执行授权。用户说先检查、先讨论或暂缓时，不进行修改或删除。

## 证据取舍

放进本档案的证据需满足：

- 轻量——不放入完整原始日志转储。
- 已脱敏——剔除主机名、账户名、完整软件路径清单、TPM 证明、内网 IP、设备序列号。
- 支撑结论——只保留得出该结论所必需的行。

完整原始转储放在本档案的 `原始采集/` 目录，该目录已写入 `.gitignore`，因此**文件在本机可见、但不进版本历史**。这样既保留未经加工的数据供复核，又避免把主机名、账户名、完整软件路径清单、TPM 证明、内网 IP 等信息永久写入 git 历史。

不要再把这些原始文件另存到会话工作目录：会话目录不具备稳定性，不作为交接入口。

## 如何持续维护

每次排查写入对应日期的记录，命名用 `YYYY-MM-DD_主题.md`；同一天多次排查则在文件名后追加区分词。更新已有记录时保留旧结果的日期，不用新结论覆盖历史事实。

实际完成并验证后才更新共享 TODO 的对应条目；仅写文件、改配置或命令能列出扩展，都不能代替实际使用验证。
